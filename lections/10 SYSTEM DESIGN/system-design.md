# Лекция 10. Системный дизайн: хранилища и кеширование

## 1. Полезные свойства хранилищ

### PostgreSQL

- Реляционная БД: SQL, JOIN, индексы, ограничения целостности.
- ACID-транзакции, MVCC, уровни изоляции и блокировки.
- WAL — журнал предзаписи для восстановления и репликации.
- Физическая и логическая репликация; синхронный и асинхронный режимы.
- Партиционирование таблиц по диапазону, списку значений или хешу; само по себе не распределяет данные по узлам.
- Встроенного автоматического шардирования между узлами нет: его реализуют вручную или внешними решениями.
- Альтернатива для распределённого SQL — БД со встроенным распределением данных: YDB, CockroachDB.

### Redis

- In-memory: рабочие данные хранятся в RAM.
- Выполнение основных команд — single-threaded на экземпляр; ввод-вывод и фоновые работы используют другие потоки.
- Структуры данных: строки, hash, list, set, sorted set (zset), геоданные, streams, HyperLogLog, Bloom-фильтры.
- Доступность отдельных типов зависит от версии и сборки.
- AOF — журнал операций; RDB — снимки данных на диск.
- Репликация и шардирование через Redis Cluster.
- TTL ключей, политики вытеснения, атомарные команды.

### ClickHouse

- Колоночная OLAP-БД: аналитика, агрегации и сканирование больших объёмов данных.
- Подходит для тяжёлых аналитических запросов и фоновых расчётов; также используется для интерактивной аналитики.
- Сжатие, пакетная загрузка, партиционирование, шардирование и репликация.

## 2. Задача: регионы и S3

Сервис электросамокатов работает примерно в 100 регионах.
При каждом запуске мобильное приложение скачивает 20–50 МБ данных текущего региона:
парковки, зоны запрета движения и зоны ограничения скорости.
Между большинством запусков эти данные не меняются. Как уменьшить трафик и время запуска?

<details>
<summary>Решение</summary>

Кешируем данные на клиенте и проверяем актуальность через ETag.
На backend кешируем или заранее собираем представление, чтобы не строить его для каждого запроса.

1. При первом запросе приложение получает снимок региона и его ETag.
2. Сохраняет данные и ETag локально, отдельно для каждого региона.
3. При следующем запуске показывает локальную копию, если требования к свежести это допускают.
4. Проверяет обновление запросом с `If-None-Match` и сохранённым ETag.
5. Если данные не изменились, сервер отвечает `304 Not Modified` без большого тела.
6. Если изменились — `200 OK` с новым снимком и ETag.
7. Приложение проверяет новый снимок и атомарно заменяет локальную копию.

Общие для пользователей снимки можно собирать при изменении данных и хранить в S3.
При необходимости CDN помогает с доставкой. Новую версию публикуем после загрузки её объекта.
Кеш backend уменьшает работу сервера, а локальный кеш и условные запросы — повторные скачивания.

Фоновая проверка не блокирует запуск, если уже есть пригодная локальная копия.
При первом запуске данные всё равно нужно скачать. Использование старых ограничений требует явного решения.

</details>

<details>
<summary>Дополнения и вопросы для обсуждения</summary>

- Определяем допустимый возраст каждого набора данных и поведение при ошибке обновления.
  Само по себе обновление в фоне не гарантирует актуальность ограничений.
- Реальные разрешения на поездку и ограничения проверяем на backend там, где это необходимо.
- Парковки и зоны ограничений можно разделить на независимо версионируемые наборы.
  Тогда изменение одной парковки не потребует скачивать все ограничения скорости.
- Сжатие и загрузка только нужной области дополнительно уменьшают объём данных.
- ETag должен стабильно соответствовать выбранному представлению.
  Не стоит заново собирать и хешировать 50 МБ при каждой проверке актуальности.
- ETag объекта S3 — непрозрачный валидатор; он не всегда равен MD5 содержимого.
- Версионируемые снимки и небольшой манифест упрощают кеширование и согласованную публикацию наборов.
- Диффы могут уменьшить загрузки, но требуют базовых версий, обработки удалений,
  пропущенных обновлений и восстановления полным снимком. Добавляем их, когда выгода оправдывает сложность.
- Что произойдёт без сети, при смене региона и при прерывании загрузки посередине?

</details>
